Evolution with an LLM as the mutator

Module 35 · Acting and planning ← All explorables

A small language model writes new versions of a bin-packing rule; a program runs each version and counts the bins. Only that count decides what survives. Everything on this page comes from the module's own runs: module 35.

1. The loop in five slides

Online bin packing

Items arrive one at a time. Each goes into an open bin with room, or into a new bin, and never moves.

The score is the number of bins, over the L1 bound: total size divided by capacity, rounded up. No packing beats L1.

Best fit, the textbook rule, ends % above L1 on our held-out instances.

A rule is a short program

def priority(item, bins):
    return -(bins - item)      # best fit: least room left

The packer calls priority with the room of every bin that can take the item, and picks the highest score.

So the search space is Python functions, and any one of them can be run and checked.

One turn of the loop

  1. Pick an island, then two parents from it, better scores more likely.
  2. Show them to the LLM as priority_v0 and priority_v1; ask for priority_v2. Four replies per prompt.
  3. Skip exact repeats. Run the rest in a sandbox with a timeout; check every packing.
  4. Keep valid children in the island. Every 25 prompts, wipe the worse two islands.

Why the checker matters

The LLM never has to be right, only to suggest. The checker decides.

Without it, each child becomes the next parent untested. In our runs that loop ended .
