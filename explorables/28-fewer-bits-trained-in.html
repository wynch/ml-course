Fewer bits, trained in

Module 28 · Using models well ← All explorables

Two places where a model can hold fewer bits. Its weights: train with each weight in {−1, 0, 1} from the start, or train in float and round afterwards; which wins when the file has a fixed size? Its KV cache: the keys and values it keeps for every past token; how few bits can they take before the model breaks? Sections 2 and 3 compute in the page; sections 1 and 4 replay what the module measured.

2 · The bf16 cast at export

A ternary model trains float "latent" weights; the file keeps only the code of each weight: −1, 0 or 1, from round(w / g) with g = mean |w|. Export tools often cast the latents to bf16 first. bf16 keeps 8 significant bits, so a latent near the threshold 0.5 · g can move across it, or onto it, where rounding a half to even gives 0. Move a latent across the threshold and watch both exports (g = 0.0821, the query-key-value matrix of section 2's model).
