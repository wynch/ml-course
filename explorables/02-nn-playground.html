Neural-net playground: train module 02's MLP in your browser

This is module 02's from-scratch net, ported line-for-line to JavaScript and training live: 2 → 16 → 16 → 2 with He-initialised Linear layers, ReLU, a fused softmax + cross-entropy loss and mini-batch SGD(momentum=0.9) over batches of 32 — the architecture, loss, optimiser and data of python/train_toy.py, 354 parameters and all.

The data is make_moons(n=600, noise=0.2), standardised per feature just as src/data.py does, generated here with a seeded PRNG so every reload is identical. Press play and watch the boundary bend around the moons; the dashed curves are the real Python run's loss and validation accuracy, so you can see whether your in-browser twin lands in the same place (it reached 97.2% on the full set after 120 epochs).

What to notice

  • The boundary is built out of straight cuts. With ReLU each hidden unit contributes one hyperplane; the curve you see is a piecewise-linear stitching of them. Switch the activation to tanh and the same net produces visibly smoother bends — that is the only thing you changed.
  • Capacity shows up as a kink budget. With ReLU, hidden = 2 usually collapses to a single class — two units, and a big early step can kill both (the classic dying-ReLU failure); 3–4 gets ~85–90%; from 6 upward it fits, and 16 (the module's choice, 354 parameters) mostly buys margin. Switch to tanh and even hidden = 2 manages ~88%, because tanh units never die.
  • Noise sets the accuracy ceiling. The moons overlap at noise = 0.2, so ~97% is the honest maximum — the real Python run scored 97.2% on the full 600 points and this JS twin lands in the same band (96–98% across seeds). Module 01's net hit 100% only because it used noise = 0.1 with 100 points.
  • Momentum multiplies your learning rate. The effective step is about lr/(1−μ), so lr = 0.3 with μ = 0.9 steps like 3.0 — right on the edge. Set the slider there and the loss curve gets the same spikes as the real Python curve (look at its epoch-83 blow-out); on some seeds it never recovers, which is exactly why the default here is the calmer 0.1.
  • Weights spread out as the net commits. The histogram starts as the He-init Gaussian (σ = √(2/fan_in)) and grows heavy tails where units have specialised. Watch layer 1 in particular: those 2 → h weights are the directions of the cuts you see in the plot.
  • Push the learning rate to 1.0+ and the same thing happens as in module 01's loss-surface explorable: the loss stops falling, the boundary thrashes, and accuracy collapses to 50% — the multi-dimensional version of the ball flying off the chart.
