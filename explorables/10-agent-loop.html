The ReAct loop

Module 10 · Breadth ← All explorables

An agent is a language model, some tools, and a loop. The model writes a Thought, then an Action naming one tool; the harness runs it and pastes the Observation back into the conversation; repeat until the model writes a Final Answer. Every transcript below is a real run of module 10's ~100-line loop driving a local SmolLM2-1.7B — including the one where it fails. Pick a task, press play, and watch the loop turn.

What to notice

  • The loop is the entire mechanism. Thought → Action → Observation, repeat. Everything fancier — planning, memory, multi-agent systems, the "agentic" products you read about — is a hardened version of exactly this cycle. Scrub the step slider and there is nothing else hiding in it.
  • Watch the failure trace. Pick the Earth-radii task. The knowledge base answers Did you mean: earth radius km? — it literally names the right key — and the model re-issues the same rejected string four more times until max_steps = 6 cuts it off. Small models loop; that transcript is shipped on purpose, and fixing it from the system prompt alone is exercise (b).
  • Code-as-action collapses turns. The two-hop task costs the hand-rolled loop two full Thought/Action/Observation cycles; the CodeAgent does it in one step because it can write calculator(f"{seconds_in_day} * 3") — a program, not a single call.
  • Report the bar, not the anecdote. The two "easy" tasks are the worst: kb_light ("just report this number") lands at 10% because the model compulsively does arithmetic on the value it looked up, and calc_expr ((5 + 7) * 3) at 20% because it rewrites the parenthesised expression. You only learn that by running each task ten times.
  • Cost varies as much as correctness. The same task finishes in 2 steps or 4 depending on the sample — and each step is a full forward pass of a 1.7B model. Ship against the distribution, not the best case.
