09read the codeNon-overlapping merge semantics

python/src/bpe.py — as printed in ALGORITHM.md §3

def merge(ids, pair, new_id):
    out = []
    i = 0
    n = len(ids)
    while i < n:
        if i < n - 1 and ids[i] == pair[0] and ids[i + 1] == pair[1]:
            out.append(new_id); i += 2
        else:
            out.append(ids[i]); i += 1
    return out

10read the codeEncoding replays merges in order

python/src/bpe.py

def encode_bytes(self, data: bytes) -> list[int]:
    """Encode raw bytes by replaying the learned merges in order."""
    ids = list(data)
    for k, pair in enumerate(self.merges):
        ids = merge(ids, pair, 256 + k)
    return ids

You “optimise” this by sorting self.merges by descending corpus frequency before the loop. What breaks?
