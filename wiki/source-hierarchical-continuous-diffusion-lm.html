Hierarchical continuous diffusion for text (H-CDLM)

Code promised at https://github.com/matol-16/HCDLM Raw copy: raw/arxiv-2610-08738-denoising-hierarchical-representations-joint-continuous-diffusion.md (full text of v1 from the arXiv HTML; cited as R, with its section)

Terms

  • Continuous diffusion language model. It turns each token into a vector, adds Gaussian noise, and trains a network to recover the clean vectors from noisy ones; generation runs that in reverse from pure noise, all positions at once (R, §3.1–3.3). Discrete diffusion models instead corrupt the tokens themselves, e.g. by masking them (R, §2).
  • Noise schedule. Which noise levels training and sampling spend their steps on. An "information-uniform" schedule spaces the steps so each reveals about the same amount about the tokens; for text that information comes out in a narrow band of noise (R, §3.3).
  • Stochastic churn. During sampling, adding a little noise back before each step, which helps these models (R, §3.3).
  • GenPPL. Generative perplexity: how surprised GPT-2 Large is by the generated text; lower reads as more fluent. A model can lower it by repeating itself, so results are compared at matched entropy of the token distribution, ideally the real data's (R, §5.1, Table 1). MAUVE scores how close the generated text distribution is to real text; higher is better.

The claim, plainly

Next to each token, diffuse a second, coarse label: which of n clusters of similar tokens it belongs to (clusters from k-means on pretrained token embeddings), and denoise both with the same network. The coarse label is easier to recover under heavy noise and steers the token toward the right region, and adding it to two continuous diffusion language models improves generation quality at about 2–4% extra compute with 16 clusters and about 1% more parameters (R, Abstract, §1, §4, §5.1, Table 12).

How it works

  • Two channels per position. The cluster's code is concatenated to the token's code at each position, each with its own noise level; the sequence length does not change, and the cluster channel is dropped at the end (R, §4.1, Figure 2). Dropping it is justified because clusters are a fixed function of tokens (R, §4.1, Appendix C.1).
  • Separate schedules and samplers. Each channel gets its own information-uniform schedule; cluster identity survives more noise, so its schedule sits at higher noise (median noise 1.13 against 0.89 for tokens) (R, §4.3, Figure 3). Churn can differ per channel, and churning clusters only in the late, low-noise half of sampling worked best (R, §4.3, §5.3).
  • Host models. Mainly CoBit, a continuous diffusion model that codes tokens as bit strings, giving H-CoBit; also FLM, a flow-matching model on one-hot vectors, giving H-FLM (R, §1, §5.4). The network is a 12-layer diffusion transformer of about 135M parameters, about 1% more than CoBit (R, §5.1).

  • Against other models. On OpenWebText at data entropy, H-CoBit with per-channel churn (50.4) is below the discrete diffusion models in Table 1 (MDLM 66.2, Duo 63.3) and the hybrid CADD (55.3); plain H-CoBit (67.8) is not. Those baselines are taken from their own papers, not re-run (R, Table 1). An autoregressive baseline scores 40.2, at entropy 5.61 rather than the data's 5.46 (R, Table 1). On GSM8K, 27.4% beats the other continuous models listed (FLM 0.3%, S-FLM 18.0%, CoBit 25.4% at 1,024 steps), but discrete diffusion models score about 33–36% and an autoregressive model 53.9–63.3% (R, Table 2).
  • The step counts differ in places. On LM1B the per-channel-churn row compares H-CoBit at 512 sampling steps with CoBit at 256 (R, Table 1); the LM1B training budgets also differ, with H-CoBit trained for fewer steps (R, Figure 1 caption).
  • Clusters must mean something. With random cluster assignments, the gain disappears; the frontier overlaps the baseline's (R, §5.3, Figure 5a). This ablation, and the choice of n = 16 clusters, were run on LM1B at 100k training steps only (R, §5.3).
  • The cluster channel adds information. Its own prediction agrees with the final token's cluster more often during sampling than the cluster implied by the token prediction, except at the very first steps (R, Appendix E.4).
  • Per-channel schedule: no clear winner. Against one shared schedule, it is slightly better at data entropy (GenPPL 57.3 vs 57.4; best MAUVE reached 0.973 vs 0.965) and worse at lower entropies (R, §5.3, Table 3).
  • It carries over to flow matching. On LM1B, H-FLM beats FLM by 11 GenPPL points at data entropy with 512 sampling steps, with stochastic sampling for both (R, §5.4, Figure 6).
  • Cost. Measured on one A100 with 16 clusters: training +1.9% to +2.5% per step, inference +2.9% to +4.2% per call; with 64 clusters, +3.2% and +5.0% (R, Appendix Table 12).

Caveats

  • Small models (about 135M) and three datasets; no scaling study.
  • Results are best-of-sweep, and the cluster loss weight "requires careful tuning for each new task" (R, §5.3).
  • Code and checkpoints are promised "upon acceptance" (R, Reproducibility statement).
