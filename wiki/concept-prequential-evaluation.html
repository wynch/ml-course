Prequential Evaluation

concept created 2026-10-20 updated 2026-10-20 evaluation prequential scoring-rules online-learning mdl benchmark-honesty stub

Stub. Prequential evaluation scores a model on a stream by prediction, then observation, one step at a time: before each new observation the model states a probability for it; the observation is then scored against that forecast, and only afterwards may the model learn from it. The name joins "predictive" and "sequential" (Dawid, "Statistical theory: the prequential approach", Journal of the Royal Statistical Society A 147, 1984; not in raw). There is no train and test split: every observation is a test before it is training data, so nothing can leak from the future.

The wiki holds no primary text on it. This page gathers the pieces that are in raw and the local work that leaned on the idea.

Key ideas

  • The usual score is the log loss. Sum −log₂ p(observation) over the stream. A predictor that does this is a compressor: likely events cost few bits, unlikely ones many (raw/arxiv-0812-4360-driven-by-compression-progress.md, Appendix A.1). So the summed log loss is a code length for the stream, and prequential evaluation is the online side of concept-minimum-description-length.
  • Use a proper scoring rule. A scoring rule is proper when a forecaster gets the best expected score by stating its true belief. Log loss and the Brier score (squared error on the stated probability) are both proper, and share the same optimum, the true class probabilities (raw/web-2026-raschka-classifier-history-and-jev.md, §5.3, citing Gneiting and Raftery, 2007). A score that is not proper can reward a model for hedging or for bluffing; see concept-calibration.
  • The whole curve, not the end point. On a stream the model learns as it goes, so the cumulative loss records how fast it learned, not only where it ended (experiment-edge-federation, Bet 1).
  • Compare against a floor stated in advance. A learner should beat a cheap baseline declared before the data arrive, such as an online mixture of simple predictors. The best single expert picked after the fact is not a fair baseline: no one could have used it (experiment-edge-federation, Bet 2).

Open questions

  • Overview gap 6 names the missing foundations: proper scoring rules, prequential codes, online mixtures of experts and switching codes (overview). Dawid (1984), Gneiting and Raftery (2007) and Blier and Ollivier (arXiv 1802.07044, prequential codes for deep networks) are the natural captures; none is in raw.
  • None of the wiki's papers on language models report prequential scores; they report fixed test sets. Would continual-learning claims (concept-continual-learning) read differently on a stream?
