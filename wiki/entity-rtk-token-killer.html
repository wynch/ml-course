RTK — Rust Token Killer

entity created 2026-05-06 updated 2026-05-06 developer-tools ai-agents token-optimization rust llm-tooling

A CLI proxy tool that filters and compresses shell-command output before it reaches an LLM context. Operates as a transparent bash hook: rewrites commands (e.g. git status → rtk git status) and passes the filtered, deduplicated, truncated result back to the agent.

Mechanism

  • Single-binary Rust tool, zero dependencies.
  • Hooks ~100+ common dev commands (git, cargo, npm, test runners, etc.).
  • Strategies: filtering, grouping, truncation, deduplication.
  • Compatible with 12 AI coding tools — Claude Code, Cursor, GitHub Copilot, Gemini, etc.

Reported Numbers

  • ~80% overall token reduction on a 30-min coding session (~118k → ~23.9k tokens).
  • Per-command: directory ops 80%, file reading 70%, git 75–92%, test runners 90%.

Why It's Interesting

  • A small, sharp instance of the harness eats compute thesis: instead of training a model to be more token-efficient, route its observations through a deterministic compressor. See concept-harness-as-symbolic-substrate.
  • Sibling in spirit to entity-codedb: both reduce per-query token cost by interposing a structured layer between the codebase and the agent.
  • Token-cost-of-context as a first-class engineering problem — adjacent to concept-long-context but tackled at the harness rather than the model.
