Optimizers

concept created 2026-10-23 updated 2026-10-23 optimization optimizers steepest-descent adam muon shampoo newton learning-rate

An optimizer turns the gradient, the slope of the loss with respect to each weight, into a change to the weights. This page sorts optimizers by one frame from Bernstein's MIT lectures: each is the step that minimises a simple local model of the loss (L7 = raw/web-2024-mit-6-7960-lec07-scaling-rules-optimization.md; L23 = raw/web-2024-mit-6-7960-lec23-metrized-deep-learning.md).

The frame

Near the current weights w, the loss is about L(w) + gᵀΔw plus a curvature term (L7, slide 10). Two ways to handle the curvature give two families:

  • Use it (second order). Newton's step Δw = −H⁻¹g uses the Hessian H, the matrix of second derivatives; it costs d² numbers for d weights (L7, slides 11–12). Gauss–Newton keeps only the error's curvature and drops the network's (L7, slides 13–15).
  • Replace it by a norm (first order). Model the curvature as (λ/2)‖Δw‖². The step is then a size, the gradient's dual norm over λ, times a unit direction that best aligns with the gradient (L7, slide 19). The norm picks the optimizer.

The step is optimal for the model, not the loss. It is safe only where the model bounds the loss from above (L23, slide 9).

The wiki's reading, not in the lectures: Adam with β₁ = β₂ = 0 (no running averages) and ε = 0 takes the step g/|g| per coordinate, which is sign descent. That explains why tiny gradients can give full-size steps unless they fall below ε. The loss spikes in source-barron-softmax-fix also need Adam's running average of squared gradients (β₂ > 0): it decays while gradients vanish and lags when they return, so the returning gradient is divided by a small number (raw/arxiv-2610-31642-a-fix-for-softmax-and-cross.md, §4–5; concept-softmax-numerics).

What the norm buys

  • Learning-rate transfer. Measured in the RMS→RMS norm, √(fan-in/fan-out) times the spectral norm, a step of a given size bounds how much a layer's output can change, by the same amount at any width; the output moves by about that much only if the bound is tight, which Bernstein assumes (L23, slide 29). Bernstein claims that setting weight and update sizes this way stops the best learning rate drifting as width grows (L7, slides 24–25; L23, slides 29–30). The shown evidence is one GPT sweep, 10k steps on OpenWebText, widths 32–1024 and 2–64 blocks (L23, slide 34). This is the aim μP (the "maximal update" parameterization) shares; see source-learning-mechanics.
  • Where the step lands. Adam's per-coordinate scaling moves a step out of the subspace its gradient lay in; source-subspace-tuning measured that in a toy run and so projects the final step (raw/arxiv-2610-22293-towards-continual-learning-mitigating-forgetting-with.md, §2.2, Appendix B.8). The spectral step keeps the gradient's row and column spaces (wiki's reading, see source-bundle-mit-6-7960-optimizer-geometry). Two caveats: it holds for the bare update only, since decoupled weight decay moves the weights along W itself, which has components in every direction; and common Muon setups update embeddings and the output head with Adam, so those matrices fall under Adam's behaviour (the wiki's note, not from these sources).

Open questions

  • Mini-batch noise: the lecture frame is full batch (L7, slide 6).
  • How tight are the modular bounds in practice? The slides show no measurement (L23, slide 29).
