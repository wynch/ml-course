GPT-4 Technical Report

source created 2026-05-06 updated 2026-05-06 openai gpt technical-report multimodal ai-alignment frontier-model system-card

Authors: OpenAI Date: March 2023 (arXiv 2303.08774)

Summary

OpenAI's ~100-page technical report for GPT-4. The paper is famous as much for what it does not say as for what it does: it is deliberately silent on architecture, parameter count, dataset composition, training compute, and training method, "given both the competitive landscape and the safety implications of large-scale models." What it offers instead is a methodology for predictable scaling, a multimodal capability claim, and an extensive system card on safety.

Key Claims

Capabilities

  • Multimodal: accepts text and image inputs, produces text output.
  • "Human-level performance on various professional and academic benchmarks": top-10% simulated bar exam, top scores on GRE, USABO, AP exams, etc.
  • Substantial improvement over GPT-3.5 on MMLU, HellaSwag, HumanEval — the benchmark sweep that defined the "GPT-4 class" tier.

Predictable scaling

  • Authors built infrastructure that lets them predict GPT-4's final loss and certain capabilities from runs at 1/1000th the compute.
  • This is the paper's main published technical contribution: scaling laws applied not as a research result but as an engineering tool for de-risking a single huge run.
  • Caveat: some capabilities (e.g. inverse scaling on Hindsight Neglect) were predicted to get worse and then didn't — capability emergence remains hard to predict in detail.

Architecture / training (deliberately withheld)

  • "GPT-4 is a Transformer-style model pre-trained to predict the next token."
  • That is essentially the entire architectural disclosure. Parameter count, data size, training compute, MoE-or-dense — all redacted.
  • This silence set a new norm: subsequent frontier reports from competitors became more secretive too, a trend only partially reversed by Llama 3 and DeepSeek-V3.

Alignment

  • Post-training via RLHF (extending source-instructgpt-rlhf).
  • "Rule-based reward models" (RBRMs) added as auxiliary signals for safety-relevant behaviours.
  • The system card section (over half the document) details red-teaming for biorisk, cyber, persuasion, and power-seeking — this is what later evolves into the preparedness / ASL / RSP frameworks at the frontier labs.

Why it matters

  • The dominant frontier model for ~18 months and the calibration anchor for every subsequent release ("matches GPT-4 on X").
  • Established the system card as the standard accompaniment to a frontier release.
  • Set the modern norm of closed technical reports — which Llama 3, DeepSeek-V3, and the open-weights wave then deliberately pushed back against.
