Summary

Two models behind Apple Intelligence: a model of about 3B parameters that runs on Apple devices, and a larger mixture-of-experts model that runs on Apple's servers ("Private Cloud Compute") (R, §1). Both read text and images, call tools and cover 16 languages (R, §1). App developers can call the on-device model through Apple's Foundation Models framework (R, §7). The wiki's note, not the report's: it is the model Apple Intelligence runs on Vincent's iPhone.

The report is a description of a product, not a set of experiments: it gives a recipe and a few tables, with no ablations and no on-device speed numbers.

The on-device model

  • Shared KV cache. The layers are split 62.5% / 37.5%. The second block has no key and value projections; it reuses the cache of the first. The KV cache shrinks by 37.5%, and prefill skips the second block, cutting time-to-first-token by about 37.5% (R, §2.1).
  • 2-bit weights, trained in. The weights are compressed to 2 bits each by quantisation-aware training (QAT): training simulates rounding in the forward pass and passes gradients straight through it (R, §6). The embedding table is at 4 bits, the KV cache at 8 bits (R, §6).
  • What made 2-bit training stable (R, §6): a learned scale per weight tensor, started from a clipping value fitted to the bulk of the weights rather than the outliers; AdamW rather than Adafactor; low learning rates; a moving average of the weights; weight decay set to 0 so weights use all four levels. The level set {−1.5, −0.5, 0.5, 1.5} trained more smoothly than {−2, −1, 0, 1}.
  • Repair adapters. LoRA adapters, trained on the base-model data with the compressed weights frozen, win back part of the quality lost to compression (R, §6).
  • Distilled from its own upcycled MoE. A dense model trained on about 14T tokens was turned into a 64-expert MoE with 1T more tokens; the dense model then retrained its last 10% of tokens (about 1.4T) against that MoE as teacher. The report says this cut the teacher's training cost by 90% (R, §4.3).
  • Vision. A 300M-parameter ViTDet-L encoder; an image becomes 144 tokens, or 9 in a fast mode at 224 × 224 pixels (R, §2.3, §5.1).

The server model

  • Parallel tracks. The network is split into several smaller transformers ("tracks") that sync only every few layers. With blocks of depth D, syncs fall from 2L (tensor parallelism) to L/D; at D = 4 that is 87.5% fewer (R, §2.2, Figure 2). Every other layer is a mixture-of-experts layer (R, §2.2).
  • Attention. Three local layers (window 4,096, rotary positions) then one global layer with no positions, repeated (R, §2.2).
  • Compression. 3.56 bits per weight after training, using a texture-compression format (ASTC) that Apple GPUs decode in fixed hardware at no compute cost (R, §6).
  • Training. 13.4T tokens on 8,192 TPU v5p chips (R, §4.3). The server model's size is not stated.

Against open models (R, Table 1–2): the on-device model scores 67.85 on MMLU, above Qwen-2.5-3B (66.37) and Gemma-3-4B (62.81), below Qwen-3-4B (75.10). The server model scores 80.20, below LLaMA 4 Scout (84.88).

  • Post-training uses RLOO, a REINFORCE variant, with reward models for preference prompts and rule checks for maths and STEM (R, §5.2.2). The new asynchronous RL system matches the old synchronous one with 37.5% fewer devices and 75% less compute time (R, §5.2.1).
  • Human graders disagree on 20–30% of the preference data (R, §5.2.2).
  • Users' private data and interactions are not used for training (R, §3).

Caveats

  • The 16-bit on-device score (67.8) is the one compared with Qwen and Gemma; the shipped 2-bit model scores 64.4, below Qwen-2.5-3B's 66.37 (R, Tables 1, 3). The text does not draw this comparison.
  • No speed, memory or energy figures for the phone; "significantly higher token throughput" is stated without a number (R, §8).
  • The human evaluations survive only as figure captions in this capture; one caption says some rivals were tested against the compressed on-device model (R, §8, Figure 4).
  • Benchmarks were run by Apple with its own settings: instruct, non-thinking versions, Apple's languages only (R, §8).
  • No ablation shows what each QAT trick is worth; "more stable" and "smoother" are not quantified (R, §6).
