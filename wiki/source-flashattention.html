FlashAttention (v1 + v2)

source created 2026-05-06 updated 2026-05-07 attention transformers efficiency gpu systems foundational

The papers that made long-context transformers economically feasible. Reframe attention as an IO problem rather than a FLOPs problem — standard attention is bottlenecked by HBM ↔ SRAM memory traffic, not arithmetic. Both versions compute exact softmax attention while reducing memory traffic by orders of magnitude.

FlashAttention v1 — Dao, Fu, Ermon, Rudra, Ré (NeurIPS 2022)

arXiv: 2205.14135. Stanford.

Method:

  • Tiling: split Q, K, V into blocks that fit in on-chip SRAM. Compute attention block-by-block in a fused kernel; never materialise the N×N attention matrix in HBM.
  • Online softmax: incrementally update softmax normaliser and running max as new K-blocks stream in (Milakov & Gimelshein 2018), so each output row converges to exact softmax without a global pass.
  • Recomputation in backward: store only softmax statistics (log-sum-exp + max), recompute attention weights on the fly during backprop. Trade extra FLOPs for memory savings.
  • Whole forward + backward is a single CUDA kernel — no intermediate tensors round-trip to HBM.

Key numbers:

  • 15% end-to-end speedup on BERT-large MLPerf, 3× faster on GPT-2 (1K seq), 2.4× on Long Range Arena.
  • Memory linear in N: trained transformers with 16K context (Path-X, 61% acc — first to beat chance) and 64K context (Path-256).
  • 25–40% of A100 peak FLOPs vs ~10% for the standard PyTorch implementation.

FlashAttention-2 — Dao, single-author follow-up (2023)

arXiv: 2307.08691. Princeton/Together AI.

Closes most of the remaining gap to GPU theoretical peak. Same exact-attention guarantee, same IO-awareness, but reorganises kernel parallelism and work partitioning for ~2× more throughput than v1.

What changed vs v1:

  • Parallelise across the sequence dimension, not just batch×heads. v1 launched one threadblock per (batch, head); v2 also splits along Q's row blocks — dramatically better utilisation when batch×heads is small (long-context inference, large models).
  • Better work partitioning between warps: v1 had warps split K into chunks (then needed inter-warp reduction through shared memory). v2 splits Q across warps and lets each warp own its output block — eliminating most shared-memory traffic on the critical path.
  • Fewer non-matmul FLOPs: rewrites online softmax to defer normalisation to end of each row, so inner loop is dominated by tensor-core matmuls.
  • Causal masking optimisation: skip blocks fully above the diagonal entirely.

Key numbers:

  • ~2× faster than v1 on A100 across head-dim 64 and 128.
  • 50–73% of A100 peak FP16/BF16 for forward attention; backward ~63% (v1 was ~25–40%).
  • End-to-end: GPT-style models train ~1.3× faster than with v1.

Why this matters

FlashAttention is the most-cited systems paper in modern LLMs. Every long-context source-attention-is-all-you-need deployment uses some descendant of this kernel — it's the default in PyTorch 2.0 (scaled_dot_product_attention), HuggingFace, vLLM, and most open-source training frameworks.

Beyond performance: it reframed the architecture-vs-systems boundary. Papers proposing approximate attention (linear, low-rank, sparse) lost most of their motivation overnight, since exact attention now ran at near-optimal hardware speed. The persistent SSM thread (source-mamba-ssm, source-mamba-2-ssm-duality) is partly a response to this — to beat FlashAttention you need asymptotically better complexity, not just smaller constants. FA-2's ~70% of peak makes that bar even higher.

The hardware-aware kernel design also recurs as a pattern in concept-model-training — moving system bottlenecks closer to silicon.
