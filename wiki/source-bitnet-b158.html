Summary

Every weight in the model's linear layers is −1, 0 or +1. Three values carry log₂ 3 ≈ 1.58 bits, hence the name (R, §1). The model is trained that way from scratch: this is quantisation built into training, not applied after it (R, §2).

How: scale each weight matrix by its mean absolute value, then round each entry to the nearest of −1, 0, +1 ("absmean"); activations are kept at 8 bits, scaled per token (R, §2, Eq. 1–3). Otherwise the model is LLaMA-like: RMSNorm, SwiGLU, rotary positions, no biases; embeddings stay in full precision (R, §2, §3). With ternary weights, a matrix product needs almost no multiplications, only additions (R, §1). The 0, absent from the first BitNet's ±1, lets a weight drop a feature (R, §1).

The baseline is the authors' own FP16 LLaMA, trained on the same 100B tokens of RedPajama (R, §3).

(R, Tables 1–2.) Smaller models trail full precision; at 3B the ternary model matches it, with 3.55× less memory and 2.71× less latency (R, §3).

  • Bigger models, bigger savings. Measured costs at 7B, 13B and 70B: the 70B is 4.1× faster than the LLaMA baseline (R, §3, Figure 2). At 70B on two A100s it fits 11× the batch and gives 8.9× the throughput, 2,977 against 333 tokens/s (R, Table 3).
  • Energy, estimated. From a standard energy model, matrix-multiply arithmetic costs 71.4× less on 7 nm chips (R, §3, Figure 3).
  • More tokens. A 3B model trained on 2T tokens averages 74.34 against StableLM-3B's 73.22 over five tasks (R, Table 4).

Caveats

  • The baseline is a reproduction, not a released LLaMA; the 2T-token comparison takes StableLM-3B's scores from its report (R, §3).
  • Table 1 does not say which dataset its perplexity is on; the text names WikiText2 and C4 validation (R, §3).
  • The 7B, 13B and 70B models were measured for cost, not trained: the paper reports no accuracy for them (R, §3).
  • Speed and memory are on GPUs with a 2-bit kernel, not hardware built for ternary weights; energy is a model, not a measurement (R, §3).
  • "Matches at 3B" rests on one run per size; on Table 2, the 3B ternary model trails on four of seven tasks and leads on three (R, Table 2).
  • The title's "all LLMs" is a programme, not a finding; the edge, long-context and hardware sections are proposals (R, §4).
