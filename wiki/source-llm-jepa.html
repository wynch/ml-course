Summary

The first try at a JEPA loss for language models, and it does not replace next-token prediction: it adds to it (R, §3.1). JEPA needs two views of the same thing. The paper takes datasets that come in pairs: an English description and its regular expression (NL-RX), a database description and its SQL query (Spider) (R, §1, Figure 2). GSM8K is used too; the paper does not spell out its two views (R, §4.1).

The loss (R, §3.1, Eq. 2): the usual next-token loss, plus λ times the cosine distance between a predicted embedding of the text and the embedding of the code.

  • Embedding: the last layer's hidden state at the last token, as in probing (R, §3.1).
  • Predictor: the same model. k special [PRED] tokens are appended to the text, and the hidden state at the last one is the prediction; k = 0 means no predictor (R, §3.1).
  • Two views in one pass: a block attention mask keeps the text and code from seeing each other, so the two embeddings take one extra forward pass in all (R, §3.1–3.2).
  • No EMA teacher, no stop-gradient and no SIGReg are described; the next-token loss stays in the objective throughout (R, §3).

  • The next-token loss does not train the JEPA term by itself. With next-token loss alone, the JEPA distance stays flat; with both, it falls while the next-token loss stays the same (R, §3.3, Figure 3).
  • The JEPA term alone produces nothing. With the next-token weight at 0, the model outputs empty strings; the JEPA term works as a regulariser on top of generation (R, Appendix A.3, Table 10).
  • Less overfitting. Over 6 epochs, plain fine-tuning starts to lose accuracy and LLM-JEPA keeps rising (R, §4.1, Figure 1).
  • Structure. After LLM-JEPA, a near-linear map takes text embeddings to code embeddings: least-squares error 4.04 against 3,035 after plain fine-tuning (R, §4.2, Table 14).
  • Pretraining, small. From random weights on NL-RX-SYNTH: 60.59 ± 1.01 against 54.38 ± 1.70 (R, Table 2). Pretrained on paraphrase groups, then fine-tuned without the JEPA term: Rotten Tomatoes 57.76 against 56.57, Yelp 27.15 against 26.46 (R, Table 9).
  • Without paired views. On NQ-Open (question, answer) and HellaSwag (context, ending): 21.59 against 20.12 and 70.51 against 69.40 (R, §5.1, Table 4).
  • Cost. Training costs up to twice as much; dropping the JEPA term on a random 50–75% of batches cuts that, and at equal compute LLM-JEPA still leads (R, §5.2, Table 6, Figure 5).

Caveats

  • Tuning is uneven. The baseline gets a learning-rate search over 4 values; LLM-JEPA then gets a further 20-point (k, λ) grid at that learning rate, and each table cell is "the best possible accuracy over a set of configurations" (R, §4.1, Tables 12–13 captions). The paper names no held-out split for that choice. The authors find no pattern in where the best setting lies (R, §6 Limitations, Figure 7).
  • Most models are 1–3B, fine-tuned on small, paired datasets. "Pretraining" means a 1B model on NL-RX or a paraphrase set, not web-scale text (R, §4.1; Appendix A.7). Some gains are small: OLMo-2-1B 87.09 to 87.52; Qwen3-1.7B on GSM8K 44.32 to 45.00 (R, Tables 12, 5).
  • The Llama-3.1-8B result (35.77 to 63.57 ± 16.81) uses a looser "starts with" grading because the model failed to stop generating (R, Appendix A.7, Table 15).
  • The ℓ2 distance in place of cosine scores 2.22%, and InfoNCE 34.40%, below the plain baseline (R, §4.3, Table 3). The paper does not say whether collapse is the reason.
