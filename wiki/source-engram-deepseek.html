Engram

source created 2026-05-06 updated 2026-05-06 transformer-architecture sparsity memory mixture-of-experts deepseek 2026

DeepSeek AI — official implementation + paper at github.com/deepseek-ai/Engram

Modernises classical N-gram embeddings as a constant-time lookup memory that augments transformer backbones, fusing static N-gram retrieval with dynamic hidden states. Engram is positioned as a sparsity primitive complementary to MoE: where MoE conditionally allocates compute, Engram conditionally allocates memory via deterministic O(1) addressing.

Key Claims

  • A new sparsity axis: trade off neural computation (MoE) vs. static memory (Engram), governed by a U-shaped scaling law that prescribes optimal allocation between the two.
  • Engram-27B beats MoE baselines under matched parameter and compute budgets across knowledge, reasoning, code, and math.
  • Mechanistic claim: Engram offloads early-layer pattern reconstruction to the memory table, freeing model depth for harder reasoning.
  • Embedding tables can be offloaded with minimal inference-time overhead.

Method

  • Engram module retrieves N-gram embeddings via deterministic hash lookup.
  • Fuses retrieved memory vectors with transformer hidden states.
  • Trained at scale, with long-context experiments showing further gains.

Connections

  • Sits in concept-transformer-architecture alongside other sparsity moves; the U-shaped MoE/memory trade-off is a new axis distinct from depth (source-keel-post-ln-highway) or matrix-residual capacity (source-residual-matrix-transformer).
  • Resonates with source-memoryllm-plug-n-play-ffn — both treat FFN-like structures as retrieval, but Engram makes the static/symbolic lookup deterministic and explicit.
  • Connects to concept-neural-symbolic-bridge: an explicit, addressable, symbolic table baked into the substrate (not learned features in superposition). A rare case of a dense LLM exposing a non-fuzzy handle.
