Calibration

concept created 2026-10-03 updated 2026-10-03 calibration evaluation classification uncertainty probability

Definition. A model is calibrated when its stated confidence matches how often it is right: among all answers it gives at about 74%, about 74% should be correct (raw/web-2026-raschka-classifier-history-and-jev.md, §5.1).

A stub, made on 2026-10-03; the wiki had no page for it.

Key ideas

  • Accuracy does not show it. Answers at 74% and at 54% both count as "positive" at a 50% threshold; only a calibration check tells whether either number means what it says (raw/web-2026-raschka-classifier-history-and-jev.md, §5.1).
  • Why trained nets drift. Cross-entropy is calibrated at its true optimum, but on a finite training set a net that already gets most examples right can keep lowering the loss by growing more confident; test loss can then worsen while test accuracy still improves (same file, §5.3, quoting Guo et al., 2017).
  • Temperature scaling. Divide the logits by one number T, fitted on held-out data with the weights frozen; T above 1 lowers confidence, below 1 raises it. The ranking of classes, and so the predicted class, does not change (same file, §5.1).
  • Calibration as a reward. RLCR rewards c − (q − c)², where c is 1 if the answer is right and q the stated confidence: the Brier penalty. A wrong answer at 0.9 scores −0.81; at 0.2, −0.04; a right answer at 0.9, 0.99 (same file, §5.2). Brier and cross-entropy share the same optimum (same file, §5.3).
  • Decision models sell it. Jev returns probabilities and confidences; TypeSafe's documentation calls them well calibrated, but neither wiki source on Jev tests that (raw/web-2026-raschka-classifier-history-and-jev.md, §3.3; raw/web-2026-simonwillison-jev-decision-models.md, opening).
