Cursor: Scaling Agents

source created 2026-04-05 updated 2026-10-20 ai-agents coding-agents developer-tools scaling

Source: Wilson Lin, "Scaling long-running autonomous coding", Cursor blog, 2026-01-14 Via: @mntruell (Michael Truell, Cursor co-founder) on X Raw copy: raw/web-2026-cursor-scaling-long-running-coding.md (captured 2026-10-20), cited below as R with its section

Summary

Cursor ran many coding agents together for weeks on single large projects and reports what worked (R, opening).

Key Ideas

  • Roles. Planners explore the codebase and create tasks (and can spawn sub-planners); workers each finish one task and push without coordinating; a judge decides at the end of each cycle whether to continue, and the next cycle starts fresh (R, "Planners and workers").
  • Locks failed. With shared locks, 20 agents ran at the effective speed of 2–3; most time went to waiting (R, "Learning to coordinate").
  • Scale. A web browser built by agents over close to a week: over 1M lines in about 1,000 files. An in-place Solid-to-React migration over three weeks: about +266K/−193K edits, passing CI but still needing review (R, "Running for weeks").
  • Models. In the author's view GPT-5.2 was best for long autonomous runs; Opus 4.5 tended to stop early and hand back control. "The prompts matter more." (R, "What we've learned")

Added 2026-10-20, from R:

  • Before the roles. Optimistic concurrency (writes fail if the state changed since the read) replaced locks and was "simpler and more robust", but with no hierarchy agents grew "risk-averse": small safe changes, no one owning hard problems (R, "Learning to coordinate").
  • Less was more. An integrator role for quality control and conflicts "created more bottlenecks than it solved" and went; workers handled conflicts themselves (R, "What we've learned").
  • Roles by model. GPT-5.2 planned better than GPT-5.1-Codex, though the latter is trained for coding; Cursor now picks a model per role (R, "What we've learned").
  • Other runs, as Cursor counts them: a video renderer made 25× faster in Rust, merged; a Java language server (7.4K commits, 550K lines), a Windows 7 emulator (14.6K commits, 1.2M lines), an Excel clone (12K commits, 1.6M lines), still running at the time (R, "Running for weeks").
  • Open problems, in Cursor's words: planners should wake when their tasks finish; agents sometimes run far too long; periodic fresh starts are still needed against drift (R, "What's next").

Caveats

  • Lines of code and commits measure output, not working software. The post gives no test pass rates, no quality measure for the browser, and no token or dollar cost beyond "trillions of tokens" (R, opening and "What we've learned").
  • The model comparison is the team's impression, not a measured result.
