Evaluation Methodology

concept created 2026-10-20 updated 2026-10-20 evaluation benchmarks contamination saturation noise methodology hub

How far to trust a benchmark score. The overview names this as a gap; the wiki's sources raise four separate problems, and each has its own check.

ProblemWhat goes wrongCheck
Contaminationthe model has seen the test, or tasks close to itprivate held-out sets; probe whether the model can recite answers
Broken teststhe checker fails right answers or passes wrong onesaudit failed tasks by hand
Saturationtop scores bunch near the ceiling, so the benchmark no longer separates systemsretire it; move to a harder set
Noise and model choicea gain sits inside run-to-run spread, or holds on one model family onlymeasure the noise band; run several families; add dummy baselines

Contamination

  • SWE-bench Verified. Every frontier model OpenAI tested could, for some tasks, reproduce the human-written fix or the task text word for word (raw/web-2026-openai-no-longer-swe-bench-verified.md, opening, "Contamination"; source-openai-swe-bench-verified-retired). The probe: GPT-5 questioned each model over 15 turns per task, a judge rated the answers, a second judge checked for leaks from the questioner, and people read the strong cases (same file, "Contamination").
  • ARC-AGI. In ARC Prize's own check, Gemini 3 used the right ARC colour names in its reasoning when the prompt never mentioned ARC or colours; the Foundation reads this as ARC data being well represented in training, an "overfitting" it "cannot precisely quantify" (raw/arxiv-2601-10904-arc-prize-2025-technical-report.md, §4.1, §4.2; entity-arc-prize). Its answer is to report state-of-the-art scores only on the semi-private and private sets (same file, §1.1).
  • Retrieval. A retrieval model can score by finding the test text in its store; RETRO's authors measure how much of their gain comes from such overlap (raw/arxiv-2112-04426-improving-language-models-by-retrieving-from.md, §2.6, §4.4; concept-retrieval-augmented-generation).

Broken tests

OpenAI audited the 138 Verified tasks o3 failed to solve consistently over 64 runs; at least 59.4% had material problems in tests or task text: 35.5% "narrow" tests that demand one implementation detail, 18.8% "wide" tests that check behaviour the task never asked for (raw/web-2026-openai-no-longer-swe-bench-verified.md, "Too narrow and too wide tests"). SWE-Bench Pro tries to fix this by giving agents written requirements and the names the tests expect. Without those additions GPT-5's score drops from 25.9% to 8.4% under a $2 cap, which its authors read as tests accepting only a narrow set of fixes (raw/arxiv-2509-16941-swe-bench-pro-can-ai-agents.md, §3.2, §6.2, Table 3; source-swe-bench-pro).

Saturation

The top Verified score rose from 74.9% to 80.9% in the six months before OpenAI stopped reporting it (raw/web-2026-openai-no-longer-swe-bench-verified.md, opening). Harder successors leave room: SWE-Bench Pro's best public score is 43.6% (raw/arxiv-2509-16941-swe-bench-pro-can-ai-agents.md, §5, Table 1); Cognition's FrontierCode Diamond split tops out at 13.4%, a figure transcribed from an announcement chart (raw/frontiercode-cognition-eval.md; source-frontiercode-cognition-eval). AIRS-Bench scores research agents against published results; agents beat the human best on 4 tasks and fail on 16 (arXiv 2602.06855; not in raw; source-airs-bench-research-agents). See concept-swe-bench for the dated scores.

Noise and model choice

  • Measure the noise band first. RRSI reruns its base harness to get a band δ and accepts a candidate only above best-so-far minus δ; on its agentic task δ is 0.4 points, and one reported evolve gain, 1.1 points, is under three times δ (raw/arxiv-2609-24972-rrsi-regularized-recursive-self-improvement.md, §3.3, Appendix D.1, Table 5; source-rrsi-regularized-harness-evolution).
  • Use more than one model family, and a dummy baseline. On Qwen2.5-Math-7B, RLVR with random rewards gives +21.4 of the +29.1 MATH-500 points that true rewards give; on Llama and OLMo the same rewards give little or nothing. Two published methods show the same Qwen-only pattern. The authors ask that RLVR claims be tested on other families and against random and format rewards (raw/arxiv-2506-10947-spurious-rewards-rethinking-training-signals-in.md, Abstract, §2.2, §3, §7; source-spurious-rewards).

Vincent's rule

idea-benchmark-honest-epistemic-loop states the same discipline for the local lines: keep truth, heuristics and exploration apart; report simple baselines first; hold out a suite the search never sees. Every local line was sunset under it (analysis-experiments-second-chance).

Open questions

  • No source here gives a general way to detect contamination; each check above is built for one benchmark.
  • Private held-out sets protect the score but stop outsiders from checking the tasks themselves.
