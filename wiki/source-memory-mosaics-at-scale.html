Memory Mosaics at Scale

Authors: Jianyu Zhang (NYU, FAIR at Meta), Léon Bottou (FAIR at Meta, NYU) Published: arXiv 2507.03285, v1 2025-07-04, v3 2026-01-14; oral at NeurIPS 2025 Raw copy: raw/arxiv-2507-03285-memory-mosaics-at-scale.md (captured 2026-10-09, full text of v3) Code: https://github.com/facebookresearch/MemoryMosaics (R, §1, footnote 2)

Every claim below cites the raw file as R, with the paper's section number.

Summary

A Memory Mosaic replaces each attention block of a transformer with associative memories. An associative memory stores key-value pairs and, given a key, returns a weighted average of the stored values: Gaussian kernel regression, an estimate of E(V | K = k) (R, §2, Eq. 2-3). When all keys have the same length, this is softmax attention (R, §2, Eq. 4).

Three things differ from attention: keys are normalised and carry an explicit bandwidth β; the query is the key itself, with no separate query map; and there is no position encoding (R, §2). The key sums up the recent past, the value looks one token ahead, so one layer can do what an induction head does ("after a, b came; a again, so predict b"), which takes a transformer two layers and position encoding (R, §3, Eq. 5).

"Memory Mosaics v2" makes three changes to reach large models (R, §3):

  • Adaptive bandwidth: β = β₁ n^α + β₀, so the kernel narrows as the memory holds more pairs n, as kernel-regression theory advises (R, §3.1, Eq. 6).
  • Gated keys: the running average that builds a key now has input-dependent weights and a gate, so that "tom-and-jerry" and "tom- - -and- - -jerry" need not get different keys, the case the paper gives against the old fixed weights (R, §3.2, Eq. 7-8). The memory still keeps every key-value pair; this is no compressed state (R, §3.2, footnote 6).
  • Three memories: a short-term memory over a 256-token window, a long-term memory over everything before a delay m, and a persistent memory, which is a plain two-layer feed-forward network (R, §3.3, §4). The split follows a plot: in the first Memory Mosaics, attention to far tokens hardly depends on position (R, §3.3, Figure 1 caption). In training m is drawn from [64, 256]; at inference m = 64 (R, §4).

Two sizes, each against a llama-style transformer with the same configuration: small (24 layers, width 2048, 200B tokens) and large (32 layers, width 4096, 1T tokens), trained at 4k context, then fine-tuned at 32k (R, §4).

The paper tests three things: knowledge stored during training, new knowledge stored from the prompt, and learning a new task from examples in the prompt (R, §5).

Key results

  • Knowledge from training: a tie. On 19 common benchmarks both large models average 52.2 (R, §5.1, Table 1). On the 13 where removing long-term memory changes little, 56.8 with it and 56.6 without, against 57.1 for the transformer (R, §5.1, Table 2). Without long-term memory the model has 8.3B parameters against the transformer's 8.8B (R, Table 2). Not every row ties: GSM8K 27.4 against 32.4, HumanEval+ 43.0 against 38.3 (R, Table 1).
  • Which benchmarks need the prompt: on the other 6, removing long-term memory drops the average from 42.1 to 34.9 (R, Appendix F, Table 9). The authors use this ablation to sort benchmarks by the memory they draw on (R, §5.1).
  • New knowledge, multi-document questions (RULER): at 32k after fine-tuning, 53.4 against 41.1 (large) and 36.9 against 22.1 (small) (R, §5.2, Table 4). Trained at 4k with no fine-tuning, the large model still scores 48.8 at 8k and 46.4 at 16k, where the table gives the transformer no score (×; R, §5.2, Table 3). Removing long-term memory drops the 32k score from 53.4 to 20.2 (R, Appendix G, Table 10).
  • Learning a task from examples (Banking77, Tacred, GoEmotion): Memory Mosaics v2 beats the transformer by "more than 10%" and improves with more examples, while the transformer gets worse with more examples (R, §5.3, Figures 3-4). With labels replaced by "class 1", "class 2", the gap holds (R, §5.3, Figure 4). Giving a transformer the same short/long memory split does not help (R, §5.3, Figure 5).
  • 8× the data does not close the gap: a transformer trained on 8T tokens scores 46.9 at 32k against 53.4 for Memory Mosaics v2 on 1T (R, §6.1, Table 5). On tasks with real labels the 8T transformer catches up; on anonymous labels the paper says more data makes the transformer worse (R, §6.1, Figures 6-7).
  • Fine-tuning to 32k: one mini-batch gives Memory Mosaics v2 a 22% gain and two reach its best; a transformer after 800 mini-batches still trails (R, §7, Figure 8).
  • Compressing models cannot do these tasks by design: an RNN, xLSTM, RWKV or state-space model must squeeze the documents before it sees the question (R, §5.2, Appendix D). Tables copied from other papers: on RULER at 2k, RWKV-v5-7B 73.7 and Mamba-2.8B 52.6 against Llama2-7B 91.6 (R, Appendix D, Table 7); on Tacred in-context, Mamba-2.8B scores 0 at every shot count (R, Appendix D, Table 8).

Caveats

  • Every in-context learning and fine-tuning result is a plot. The raw copy keeps captions only, so "more than 10%", "22%" and "800 mini-batches" are the paper's words, not numbers this wiki can check (R, §5.3, §6.1, §7).
  • Two text summaries do not match their tables. §5.2 says the 4k gain is 1.4% to 5.6%; Table 3 gives 59.3 against 57.7 (large) and 45.0 against 39.4 (small), gaps of 1.6 and 5.6 by our subtraction. Appendix G says removing long-term memory costs "20%∼30%"; Table 10 gives the scores with and without it, and our subtraction puts the drops at 20.4 points (58.9 − 38.5, at 4k) to 34.9 (54.9 − 20.0, at 16k) (R, §5.2, Table 3; Appendix G, Table 10).
  • The 8T transformer is not the same recipe: it uses grouped-query attention and trains at 8k context (R, §6.1, Table 5 caption). The 200B and 1T transformers do not.
  • The large Memory Mosaic is bigger: 9.9B parameters against 8.8B, and 18.9B FLOPs per token against 16.7B, the FLOPs counted at context length 256 (R, Table 2). The paper says the 10% lead holds at equal FLOPs or parameters, in a plot (R, §5.3, Appendix E, Figure 12). No wall-clock times; efficiency "is not the goal" (R, Appendix E).
  • The hyperparameters were tuned for the transformer and reused unchanged, which the authors say may be suboptimal for their own model (R, Appendix C).
  • No state-space model or RNN was trained here; their failures come from other papers' tables, at other sizes (R, Appendix D).
  • Table 11's comparison with public 7B models uses copied numbers and a shorter answer length for Memory Mosaics v2 (32 against 128 tokens) (R, Appendix G, Table 11).
  • For each n-shot task the best of several prompt formats is kept, for both models (R, §5.3, footnote 13).
