The Topological Trouble With Transformers

source created 2026-06-18 updated 2026-09-26 transformers architecture state-space-models recurrence llm-reasoning

Authors: Michael C. Mozer, Shoaib Ahmed Siddiqui, Rosanne Liu (Google DeepMind) Date: 2026-04-18 (v1); revised 2026-06-03 (v3) arXiv: 2604.17121

Summary

A position/perspective article arguing that the transformer's purely feedforward architecture has a structural ("topological") limit on dynamic state tracking, and that temporally extended cognition should come from recurrence in activation dynamics rather than from externalized thought traces.

Key Ideas

  • Filtering vs retrieval. The RNN→transformer transition swapped state-based filtering (iteratively update a latent as the environment evolves) for history-based retrieval (keep the whole context window, use self-attention for non-local lookups). Retrieval is not the same operation as state tracking.
  • Depth exhaustion (the topological trouble). A feedforward stack must push an evolving state one layer deeper per input step. With fixed depth, a transformer eventually runs out of layers for genuinely sequential state updates — information becomes inaccessible in shallow layers.
  • Workarounds are inefficient. Dynamic-depth models, explicit chain-of-thought "thought traces," and latent/continuous thinking all externalize state to dodge the depth limit, but at a compute and memory cost.
  • The argument: prefer implicit activation dynamics via recurrence over explicit externalized thought.
  • Taxonomy. Recurrent / continuous-thought transformer variants are organized by recurrence axis (depth vs step) and ratio of input tokens to recurrence steps.
  • Directions: enhanced state-space models and coarse-grained recurrence integrated into foundation models.

Connections

  • Sharpens the open questions in concept-transformer-architecture about recurrence vs depth and whether hybrid architectures will dominate pure transformers.
  • The recommended fixes point at the SSM/recurrence literature: source-mamba-ssm, source-mamba-2-ssm-duality, source-olmo-hybrid-rnn-transformer, source-ttt-kv-binding-linear-attention.
  • The "externalized thought is inefficient" critique connects to thread-test-time-compute, source-pdr-rethinking-thinking-tokens, and source-recursive-language-models.
  • Complement to source-next-latent-prediction: this paper diagnoses the missing recurrent/state-tracking inductive bias; NextLat adds one back via a self-supervised objective without changing the architecture.
  • source-abstract-token-curriculum trains continuous thoughts and measures the cost this paper names: backward memory grows with the chain length; backpropagating through the last 5 thoughts cuts peak memory to 27% but works only with curriculum backtracking (97.4% vs 51.0%); the forward pass stays linear in chain length (raw/arxiv-2609-19717-learn-your-own-thoughts-abstract-token-curriculum.md, §6.3, Table 2).
  • source-coconut-continuous-latent-reasoning — a chain of n continuous thoughts needs n + 1 sequential forward passes in training, which the authors name as a parallelism problem (raw/arxiv-2412-06769-coconut-reason-in-continuous-latent-space.md, §3).
  • source-recurrent-depth-latent-reasoning — a depth-axis recurrent model in this taxonomy: one block looped up to 132 effective layers.
  • Contradiction (partial): the abstract (the only part in this page's raw copy) calls dynamic-depth models and latent thinking "computationally and memory inefficient". The recurrent-depth paper argues its looped model needs less memory than chain-of-thought in training and inference, and fixes training memory by backpropagating through the last 8 loops only (raw/arxiv-2502-05171-recurrent-depth-latent-reasoning.md, §2, §3.3). The two compare against different things: this paper against built-in recurrence over steps, that one against written chains. The abstract does not say whether a looped block counts as a costly dynamic-depth model or as the recurrence it favours; if the latter, the two agree.
