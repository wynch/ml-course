WikiSkill — A Persistent Wiki Behind Agent Skill Evolution

source created 2026-09-10 updated 2026-09-10 llm-agents agent-skills self-improvement continual-learning harness benchmarks

Authors: Liyan Tang, Cyrus Rashtchian, Chun-Sung Ferng, Andrew Tomkins, Da-Cheng Juan, Tu Vu (Google) · arXiv: 2608.27454v1 · Date: 2026-08-27

Summary

Skill-evolution systems let an agent read its own execution traces and write itself better instructions. The complaint here is that the reasoning behind each edit evaporates: only the edited skill file survives, so the next iteration re-derives (or repeats) what the last one learned. WikiSkill adds a third layer between traces and skills. raw/ holds immutable traces. wiki/ holds markdown pattern pages naming failure modes and workarounds, plus an evolution log and a skill-impact.md audit trail written by the harness recording every proposal's diff, validation score, and accept/reject verdict. skills/ holds the active instructions. A four-part loop runs each iteration: the Inference Agent solves tasks with the current skills; a Wiki Maintainer does root-cause analysis on sampled traces and patches the wiki; a Skill Proposer reads the wiki index and the audit trail, pulls specific traces on demand, and proposes one atomic skill edit; a validation gate accepts it only if the score strictly improves, else rolls the skills back. The wiki is never rolled back — that asymmetry is the whole design.

Key claims

  • Best average on all five inference models. Against the strongest competing skill-evolution method per model, WikiSkill gains +3.3 / +5.1 / +10.0 / +5.8 / +12.0 average points (Qwen-3.5-4B, Qwen-3.5-9B, Qwen-3.6-27B, Gemma-4-31B, Gemini-3.5-Flash) across five benchmarks: LiveMath, SealQA, SpreadsheetBench, OfficeQA, ALFWorld. Three full evolution runs averaged; paired bootstrap at p<0.05.
  • Some single-task jumps are large. Gemini-3.5-Flash LiveMath 33.0% → 72.6% and SpreadSheet 50.5% → 76.6%; Qwen-3.6-27B ALFWorld 52.8% → 77.6%.
  • Skills substitute for scale, partially. Qwen-3.5-9B with skills averages 47.4% against Qwen-3.6-27B without skills at 39.4%. But the gain also grows with scale within the Qwen family: +12.3, +17.5, +23.9 points at 4B, 9B, 27B.
  • The wiki is the active ingredient. Ablation on Gemini-3.5-Flash: giving the Skill Proposer wiki access lifts the five-benchmark average from 48.7% to 63.7% (+15.0). Removing the wiki also removes the Maintainer, so this measures persistent accumulation as a whole, not one component.
  • Counterintuitive result: wiki access hurts the solver. Letting the Inference Agent read the wiki during training rollouts drops the average from 63.7% to 60.9% (LiveMath 72.6% → 64.8%). The authors' hypothesis: the agent solves from the wiki instead of from the skills, so the traces stop revealing what the skills are missing.
  • Skills transfer, sometimes better than self-evolved ones. Qwen-3.6-27B skills lift Qwen-3.5-9B on SpreadSheet to 50.5%, against 24.3% no-skill and 33.6% self-evolved. Small-to-large works too: Qwen-3.5-4B skills lift Gemma-4-31B to 73.1% on LiveMath.
  • Negative transfer is real and large. Qwen-3.5-4B SpreadSheet skills drop Gemini-3.5-Flash from 50.5% to 18.1% — the small model's low-level workarounds block the strong model from writing end-to-end scripts, and its fragmented diagnostics burn the interaction budget.

Limitations (stated by the authors)

  • Retrieval is deliberately not tested. All active skills are injected wholesale into the system prompt, following prior work, to remove retrieval failure as a confound. The paper says triggering and selection become important as the skill count grows, and leaves them open.
  • The strict validation gate rejects neutral proposals that might have paid off an iteration later.
  • No pruning mechanism — the wiki only grows.
  • No very-long-horizon tasks (hundreds of actions, multi-hour runs); no within-rollout adaptation.

Relevance

  • concept-ai-agents and source-bundle-agent-harnesses — the natural successor to source-voyager-minecraft-skill-library's skill library and source-reflexion-verbal-rl's verbal memory: the new claim is that the derivation must persist, not only the artifact.
  • concept-harness-as-symbolic-substrate — the wiki is symbolic substrate in its purest form: markdown pages, an index, a log, a diff-level audit trail, all outside the weights and all readable by a human.
  • concept-self-improvement — a clean separation the paper draws out: discovering useful procedure and executing it are different capabilities, and small models can do the first well while failing at the second (OfficeQA — Qwen-3.5-4B's own skills hurt it, 30.2% → 28.5%, but lift Qwen-3.6-27B, 42.1% → 52.9%).
  • experiment-weights-vs-context — same axis, opposite corner: WikiSkill puts everything in context and never touches weights, and gets 12–24 average points that way.
  • Local counterpoint — the crystallizer (../ml-lab/crystallizer/RESULTS_V2.md) tested exactly the variable WikiSkill excludes. There a library of learned cards scored 0.40 against a 0.29 no-library baseline, and the write-up is explicit that refusing to fetch was the only fix that paid: v0's shelf, which always returned its nearest card, produced 43 wrong cards and was a net liability; teaching the index to stay quiet on a mismatch turned it into the nine-point gain. On the harder eighteen-rule family a looser index "answered more and knew less" and lost to the narrow one. WikiSkill's injection-everything setup cannot see this failure — but its own negative-transfer number (50.5% → 18.1%) is the same lesson arriving through a different door: an unsuitable piece of learned procedure costs more than none. The scales are not comparable (100 episodes on synthetic string rules vs five agent benchmarks); the direction agrees.
