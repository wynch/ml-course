Does RL Really Incentivize Reasoning Beyond the Base Model?

Summary

RLVR is reinforcement learning with verifiable rewards: the model gets 1 when a checker says its final answer is right (or its code passes the tests) and 0 otherwise (R, §2.1). The common belief is that RLVR, like RL in Go or Atari, lets a model find new ways to reason. The paper tests that belief by comparing each RL-trained model with the base model it started from, using pass@k at large k: a problem counts as solved if any of k samples is right, so pass@k measures how many problems a model can solve, not how often it gets them right (R, §1, §2.2).

The finding: RL-trained models win at small k (k = 1 is ordinary accuracy), but as k grows the base model catches up and then wins, on every benchmark and model family tested. RL makes right answers more likely on problems the base model could already solve; it does not add problems the base model could never solve, and it loses some (R, Abstract, §3, Figure 2).

Key results

  • Crossover in maths. Qwen2.5 7B, 14B and 32B base models and LLaMA-3.1-8B, with zero-RL models from SimpleRLZoo (GRPO, correctness reward only), on GSM8K, MATH500, Minerva, Olympiad, AIME24 and AMC23: RL leads at k = 1, the base model leads at large k. On Minerva at 32B, the base model solves about 9% more problems at k = 128 (R, §3.1, Figure 2). Oat-Zero and DAPO start "nearly 30% higher" than their base models and are still overtaken (R, §3.1, Figure 11).
  • Same in code and vision. CodeR1-Zero-Qwen2.5-7B and DeepCoder-14B on LiveCodeBench, HumanEval+ and MBPP+, and Qwen2.5-VL-7B on MathVista and MathVision, show the same crossover (R, §3.2, §3.3, Figures 3, 4). Code answers are checked by unit tests, so lucky guesses cannot explain the base model's wins (R, §3.2).
  • Solved sets nest. On AIME24 (k = 1024), 13.3% of problems are solved by the base model only and 0.0% by the RL model only; on MATH500 (k = 128), 3.6% and 1.0% (R, §4.1, Table 2).
  • RL paths are base paths. The base model gives RL-model answers low perplexity, matching the base model's own likeliest answers; this perplexity falls as RL training goes on (R, §4.1, Figure 6, Appendix C.4).
  • Coverage shrinks with training. Over RL steps, training-set pass@1 rises from 26.1 to 42.5 while pass@256 falls (R, §4.4, Figure 1 right).
  • Six algorithms, one ceiling. PPO, GRPO, Reinforce++, RLOO, ReMax and DAPO, re-run under one framework, all leave a gap of over 40 points between the RL model's pass@1 and the base model's pass@256 (from RLOO's 42.6 to GRPO's 43.9 on the in-domain test) (R, §4.3, Figure 8).
  • Distillation is different. DeepSeek-R1-Distill-Qwen-7B, trained on a stronger model's reasoning traces, lies above its base model at every k (R, §4.2, Figure 7).
  • Not entropy alone. Raising the RL model's sampling temperature to match the base model's entropy helps a little but does not close the gap (R, §4.5, Figure 18).
  • Near the frontier. Magistral-Medium against its base, Mistral-Medium-3: about 7 more AIME24 and 8 more AIME25 problems at k = 1, a gap that narrows as k grows (R, §4.6, Figure 9).

Caveats

  • Pass@k in maths can reward a lucky guess. The authors checked chains of thought by hand on the hardest solved problems: on GSM8K, 24 of 25 base-model problems had at least one correct chain; on AIME24, 5 of 6 (R, §3.1, Appendix C.2). The check covers a subset only.
  • Base models were prompted zero-shot with the RL prompt, with no few-shot examples (R, §3). That is fair to RL, and the base model still wins at large k.
  • Most RL runs are short and on open recipes; the strongest proprietary pipelines could not be tested, and the authors leave open whether much longer RL training changes the result (R, §4.4, §4.6, §7). source-prorl is the direct reply on that point.
  • Contradiction (open), 2026-10-19: source-prorl reports that RL run for over 2,000 steps, from a distilled 1.5B model and on tasks beyond maths, solves problems the start never solved in 256 samples (raw/arxiv-2505-24864-prorl-prolonged-reinforcement-learning-expands-reasoning.md, §4.3). On maths it reports the same narrowing found here (same file, §4.2).
  • "The base model can solve it at k = 1024" is a statement about coverage, not usefulness: nobody samples 1,024 answers without a checker (R, §2.2).
