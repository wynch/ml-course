We Should Take Text Optimization More Seriously

source created 2026-07-04 updated 2026-09-25 prompt-optimization in-context-learning ai-agents self-improvement memory harness

Author: Yoonho Lee (Stanford AI Lab; Google Student Researcher) / Date: 2026-06-08 / Type: blog post / X article

Summary

Yoonho Lee argues against a "common negative sentiment among ML researchers toward prompting" — the view that real learning happens in the weights. He defines text optimization broadly as any method that modifies the mutable text layer around a model: prompts, context, filesystem state, memory, retrieval databases, and harness code. His thesis is that this layer is a first-class update mechanism — functionally the same role as gradient-based weight optimization (changing future behavior in response to new information) — and deserves the same research seriousness the field gives to weight optimization.

Three positive arguments. (1) Legitimacy: once a deployed AI system is viewed as a stateful machine with many behavior-conditioning states (weights being just one), "learning" means changing any of them; the question is which update target fits a given piece of information. (2) Sample efficiency: short, high-likelihood text has low description length (a Kolmogorov/MDL-style prior), so text edits are "compact patches to a pretrained world prior" and are orders of magnitude more sample-efficient in the low-data regime — hence the industry pattern of eliciting behavior via text, then distilling into weights over time. (3) A new scaling axis — update-time compute: reflective text optimization (Reflexion, Trace, GEPA, Meta-Harness) lets a system externalize hypotheses about how it should change and test them before committing, spending more compute to learn from a single experience — the analogue of inference-time scaling for a single input. SGD can't cheaply do this because its single running parameter vector commits each update.

The piece then steel-mans the case for weights (amortization, new-circuit creation, optimizer theory, universal approximation, portability) and rebuts each — reframing the choice as a routing problem: weights are for stable, repeatedly-useful information; text is where information stays while it is volatile, local, auditable, or not yet trusted enough to amortize. He closes with a "call for good research on the text layer": theoretical analysis (PAC-Bayes on prompts), better evals that control for weight capability, "architecture research" mapping the design space (instruction hierarchy, DSPy programs, agent skills, memory systems), HCI for eliciting expert input, and seriously scaling up text optimization (a Wikipedia-scale knowledge/harness layer with its own scaling laws).

Key Ideas

  • The text layer as an update target. Prompts/context/memory/retrieval/harness = mutable state that conditions future behavior, on par with weights.
  • MDL prior. Text updates are compact, high-likelihood patches to a pretrained prior → large sample-efficiency advantage in low-data regimes.
  • Update-time compute as a new scaling axis: reflective, hypothesis-testing text optimization spends compute to learn from one experience.
  • Routing framing. Weights = stable/general/amortizable info; text = volatile/local/auditable/not-yet-trusted info. Text as a staging ground before distillation into weights.
  • Reachable behavior, not representational capacity, is the right lens; harnesses execute behaviors a frozen forward pass wouldn't reach.
  • Call to action: theory (PAC-Bayes on prompts), evals (CL-bench, TerminalBench-2), a taxonomy of the design space, HCI, and scaling laws for text optimization.
