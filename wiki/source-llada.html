Summary

The question: do scale, in-context learning and instruction following need left-to-right (autoregressive) generation? The authors say no: those come from maximum-likelihood training, not from the left-to-right form (R, §1).

LLaDA is a masked diffusion model. In training, pick a ratio t between 0 and 1, hide each token with probability t, and train a Transformer with no causal mask to predict the hidden tokens; the loss counts only hidden tokens and is weighted by 1/t, which makes it an upper bound on the negative log-likelihood (R, §2.1, Eq. 3–4). BERT hides a fixed share; MaskGIT drops the 1/t term; the authors say that bound is why they dared to scale (R, §2.1).

Generation starts from a fully hidden answer of chosen length. Each step predicts every hidden token at once, then hides again the least confident share, until none is left (R, §2.4). Fine-tuning hides only answer tokens (R, §2.3).

LLaDA 8B: pretrained from scratch on 2.3T tokens with 0.13M H800 GPU-hours, then fine-tuned on 4.5M pairs; no reinforcement learning; each run done once, with no hyperparameter tuning (R, §1, §2.2, §2.3).

Key results

  • Same data, same compute. Against autoregressive baselines trained on the same data, from 10²⁰ to 10²³ FLOPs, LLaDA matches the overall trend on six tasks and scales better on MMLU and GSM8K; it trails on PIQA, with the gap shrinking (R, §3.1, Figure 3). The authors fit no curves. Only the 1B pair shares an architecture; at the top, LLaDA 8B is compared with a 7B autoregressive model (R, Appendix B.2).
  • Against LLaMA 3 8B, base models. MMLU 65.9 vs 65.4; GSM8K 70.3 vs 48.7; MATH 31.4 vs 16.0; HumanEval 35.4 vs 34.8; but BBH 49.7 vs 62.1, HellaSwag 70.5 vs 79.1, PIQA 73.6 vs 80.6. LLaMA 3 saw 15T tokens to LLaDA's 2.3T (R, Table 1). The authors put the differences down to data they cannot compare (R, §3.2).
  • After fine-tuning. LLaDA 8B Instruct (fine-tuning only) trails LLaMA 3 8B Instruct (fine-tuning plus RL) on most rows: GSM8K 69.4 vs 78.3, HumanEval 49.4 vs 59.8; it leads on ARC-C 88.5 vs 82.4 (R, Table 2).
  • Reversal curse. On 496 Chinese poem line pairs, asked for the next or the previous line: GPT-4o 82.7 forward, 34.3 reversed; Qwen2.5-7B Instruct 75.9 and 38.0; LLaDA 8B Instruct 51.8 and 45.6 (R, §3.3, Table 4). The model is weaker going forward but loses little going backward.
  • Speed and memory. With no KV cache, LLaDA's throughput beats LLaMA 3 (with cache) by 1.5× on GSM8K and 1.8× on MATH at similar quality, set by the number of sampling steps (one A100, batch 1); on MBPP it lags (R, Appendix B.7). Memory is close to LLaMA 3 without a cache and a little above it with one (R, Table 11).

Caveats

  • The datasets differ from LLaMA's, and the 8B comparison to its own autoregressive baseline is not size-matched (R, §3.2, Appendix B.2, §5).
  • Sampling settings matter: block-style sampling raises the Instruct model's GSM8K from 69.4 to 78.6, because padding in the fine-tuning data makes the default sampler stop early (R, §3.2).
  • Answer length is a setting the user picks; no KV cache or special attention was built (R, §5).
  • Data leakage on GSM8K is argued against with a held-out GSM8K-like task (R, §3.2, Appendix B.8).
