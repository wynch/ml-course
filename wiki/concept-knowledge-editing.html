Knowledge Editing

concept created 2026-10-20 updated 2026-10-20 knowledge-editing factual-memory rome memit memory-layers continual-learning hub

Knowledge editing changes one fact a model holds ("the Eiffel Tower is in Rome") without retraining it and without disturbing the rest. It sits between three neighbours: fine-tuning, which changes much more than one fact; concept-machine-unlearning, which removes rather than rewrites; and concept-retrieval-augmented-generation, which leaves the weights alone and puts the fact in the prompt.

Two routes

Find the fact, then edit it. ROME adds noise to the subject's tokens, then restores single hidden states from a clean run to see which one brings the answer back ("causal tracing"). The answer: middle-layer MLPs reading the subject's tokens. It then rewrites the fact with a rank-one change to one MLP's weights, treating the MLP as a key-value store; MEMIT spreads many such edits over several layers (arXiv 2202.05262, §2.1; arXiv 2210.07229; neither in raw; source-rome-memit-factual-editing).

Build a store that is easy to edit. Put facts where each input touches only a few weights, and train only those.

  • Sparse memory finetuning replaces one middle MLP of a 1.3B model with a lookup table of 1M slots; each token reads its top 32 per head. To learn a fact it trains only the slots that fact's batch uses far more than ordinary text does (raw/arxiv-2510-15103-continual-learning-via-sparse-memory-finetuning.md, §3, §4, §5). Learning 1,000 facts in sequence, NaturalQuestions F1 drops 11%, against 89% for full fine-tuning and 71% for LoRA (same file, Abstract, §1). About 25–100 trained slots were enough for the examples shown (same file, §6, Table 1). source-sparse-memory-finetuning
  • Engram adds a table of n-gram embeddings, found by hash lookup, beside the network (raw/arxiv-2601-07372-conditional-memory-via-scalable-lookup-a.md, §1, §2); a 100B-parameter table kept in host memory costs under 3% at inference (raw/arxiv-2601-07372-conditional-memory-via-scalable-lookup-a.md, §1; source-engram-deepseek). It is built for capacity, not editing; whether one entry can be rewritten cleanly is untested here.
  • MemoryLLM makes the feed-forward blocks an interpretable memory that can be plugged in and out (arXiv 2602.00398; not in raw; source-memoryllm-plug-n-play-ffn).
  • For removal, NULLs route each source's knowledge to its own sparse "sinks" that can be switched off at deployment (raw/arxiv-2606-13873-natively-unlearnable-llms.md; source-natively-unlearnable-llms; concept-machine-unlearning).

Does finding the fact help edit it?

Contradiction (open), carried from source-rome-memit-factual-editing: Hase, Bansal, Kim and Ghandeharioun ("Does Localization Inform Editing?", NeurIPS 2023, arXiv 2301.04213) find that where causal tracing places a fact does not predict which layer edits it best (not in raw). If so, ROME's edit works, but not for the reason its trace gives. The built-in stores above sidestep the question: they choose where facts go before training.

Open questions

  • None of ROME, MEMIT or Hase et al. is in raw. Capture them before weighing the contradiction.
  • Sparse memory finetuning was tested only on facts, at 1.3B; its authors name reasoning and coding as harder (raw/arxiv-2510-15103-continual-learning-via-sparse-memory-finetuning.md, §7).
  • Edits to a fact's consequences ("so the Eiffel Tower is in Italy") are not measured by any source here.
