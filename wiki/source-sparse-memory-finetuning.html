Sparse memory finetuning

Summary

Fine-tuning on new facts makes a model forget old ones because every fact shares the same weights (R, §1). The authors' bet: store knowledge where each input touches only a few weights, and train only those.

The store is a memory layer. One feed-forward block in the middle of the transformer is replaced by a lookup into a table of 1M learned keys and values; each token picks its top 32 keys per head and blends their values (R, §3, Figure 1). Each token so touches a tiny share of the table (R, §3).

Sparse memory finetuning trains only some of the slots a batch touched: those it touched often that ordinary text rarely touches. The ranking is TF-IDF, the old search-engine score, with 1,000 batches of pretraining text (DCLM) as the "ordinary" side. Only the top t slots get gradients; everything else stays frozen (R, §4).

Key results

The base model has 1.3B parameters; the memory layer sits at layer 12 of 22 (R, §5).

  • Learning facts one at a time. Trained in sequence on 1,000 TriviaQA facts, each as a batch of paraphrases: NaturalQuestions F1 drops 89% with full fine-tuning, 71% with LoRA, 11% with sparse memory finetuning, for "the same level of new knowledge" (R, Abstract, §1). The scores themselves are in a chart only (R, §5.1, Figure 3). Here t = 500 slots per step was enough (R, §5.1).
  • Learning from documents. On 1,824 Wikipedia chunks behind 100 SimpleQA questions, one chunk per step: full fine-tuning and LoRA reach the same target score but forget more on held-out tasks (R, §5.2, Figure 4).
  • The trade-off curve. Across sweeps of learning rate, rank and t, sparse memory finetuning learns as much while forgetting less on HellaSwag than any setting of the others (R, §6, Figure 5).
  • Both parts are needed. Tuning every slot the batch touched, or ranking slots by count alone, forgets more; full fine-tuning of the memory model forgets badly (R, §6, Figure 6). Ranking against the training facts themselves, instead of ordinary text, forgets much more (R, §6, Figure 7).
  • Facts are spread thin. About 100–500 slots carry what a fact's paraphrases and its question share; 25–100 trained slots were enough to answer the examples shown (R, §6, Table 1).

Caveats

  • The optimizers differ. Baselines use AdamW; sparse memory finetuning uses SGD, which cut its forgetting further. With SGD the baselines forget less but learn less: their best TriviaQA F1 is 0.58–0.65 at NQ F1 0.01–0.09; the caption gives sparse memory TriviaQA F1 "> 0.7", NQ F1 "< 0.15" (sic) and GSM8K NLL "< 1.5" (R, §5, Appendix A, Table 2). So part of the gap is the optimizer.
  • The memory model starts with more knowledge than the plain model (R, §5.1, footnote 1).
  • Only fact learning on one 1.3B model; the authors name harder tasks, bigger models and retrieval (RAG) as the obvious rival they did not test against (R, §7).
