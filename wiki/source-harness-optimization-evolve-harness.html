Don't Train the Model, Evolve the Harness

source created 2026-07-04 updated 2026-09-26 ai-agents harness-as-substrate benchmarks self-improvement developer-tools evaluation legal

Author: Joel Niklaus (Hugging Face) / Date: 2026-07-01

Summary

Niklaus applies the Meta-Harness loop to Harvey's Legal Agent Benchmark (LAB): freeze an open model (deepseek-ai/DeepSeek-V4-Pro) and let an automated search rewrite only the harness — the runtime wrapper that feeds the model documents, exposes tools, executes tool calls, and decides when a run ends. A frozen model that solved 0% of LAB end-to-end was lifted, with zero weight changes, from 63.4% to 80.1% pooled criterion pass rate on a held-out test split (0% -> 5.0% whole-task all-pass), landing between Sonnet 4.6 and Opus 4.6 on LAB's headline metric at far lower cost. The framing is the "mismanaged geniuses" hypothesis (Zhang et al., 2026): a weak benchmark score often measures the scaffold, not the model — an LAB agent can read the documents, spot the issues, write a sound analysis, then save it under the wrong filename so the judge (which only reads top-level output/ files under the exact requested name) scores it zero.

The loop is a reflect-mutate-keep search over harness code. A Claude proposer (Opus 4.8) reads the run history, copies the current best harness, and adds exactly one mechanism; an outer Python scaffold re-runs the candidate on a frozen 24-task dev set (3 trials each) and promotes it only if a blended score (pooled + 0.5*all_pass - 0.005*tokens_per_million) beats the incumbent by ≥1 point, just above three-trial noise. Two rules keep the search honest: copy-and-adapt one mechanism at a time (so wins compound and stay readable in a flat file), and never read the held-out test split. A single evaluation run costs $120–$160, dominated by ~6,300 Sonnet judge calls, which is why the dev set stays small.

The findings are pointed. Five of the top six harnesses are deterministic code, not prompt edits — the biggest single gain was a post-solve step that deterministically lands the deliverable at the top of output/ under the exact requested name, with zero extra model tokens, turning near-zero scores into scored work. Other gains: a matter-fidelity check that catches drafts about the wrong (distractor) matter, tool-call JSON repair, and loop-breaking. Prompt "playbooks" helped early but plateaued. Crucially, code and robustness mechanisms transfer across model families while prompt playbooks are model-specific and can backfire (DeepSeek V4 Flash +14.4 pts; different-family Nemotron-3 Ultra +0.4 pts, its tool-call fixes helping but its inherited prompts hurting). An external-harness bake-off drives the thesis home: same model and judge, wrappers scored 3.5% (mini-swe-agent), 23.2% (Goose), 45.4% (Pi), 63.4% (stock LAB), 80.1% (optimized) — "the mismanaged-geniuses hypothesis in numbers."

Key Ideas

  • Freeze the model, search the harness: an automated Meta-Harness loop (Claude Opus 4.8 proposer + strict Python verifier) rewrites the scaffold around a fixed open model.
  • +16.7 pts held-out (63.4% -> 80.1% pooled; 0% -> 5.0% all-pass) on LAB with zero weight changes; open model reaches Sonnet-4.6-to-Opus-4.6 territory at lower cost.
  • The dominant wins are deterministic I/O discipline (deliverable landing/reassembly, matter audit, tool-call repair), not prompt engineering — 5 of top 6 harnesses are code.
  • Transfer asymmetry: code/robustness mechanisms generalize across model families; prompt playbooks are model-specific and can regress other models.
  • Blended objective + one-mechanism copy-and-adapt + no-test-peeking make the search auditable; the hard part is the verifier (LAB's dense criterion-by-criterion LLM rubric).
