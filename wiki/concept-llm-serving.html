LLM Serving

concept created 2026-09-26 updated 2026-10-03 inference serving kv-cache systems

Definition. Running a trained language model for many users at once: turning a stream of requests into tokens fast and cheaply. Training asks how to fit the weights; serving asks how to share one GPU's memory and time among many requests.

Key ideas

  • Two phases. Prefill reads the whole prompt in one pass and is usually compute-bound. Decode makes one token per pass and is memory-bandwidth-bound, since each pass reads all the weights (raw/web-2025-aleksagordic-inside-vllm.md, §"Scheduler").
  • KV cache. Keys and values of past tokens are kept so decode does not recompute them. The course builds one by hand and measures the gain: 63× at 128 tokens of context (course/modules/07-inference-internals/README.md, "The KV cache lab").
  • Paged cache and continuous batching. The cache lives in fixed-size blocks, so many requests of any length share memory, and requests join or leave the batch after any step (raw vLLM file, §"Scheduler"; §"Run forward pass").
  • Reuse and shortcuts. Prefix caching reuses the cache of a shared prompt start; speculative decoding checks several guessed tokens in one pass without changing the output distribution (raw vLLM file, §"Prefix Caching"; §"Speculative Decoding"). One essay says the drafter is now often a small diffusion model that guesses a whole block in one pass (DFlash), shipped in SGLang, vLLM, TensorRT-LLM and llama.cpp (raw/web-2026-varunneal-diffusion-everywhere.md, "The case from inference", footnote 8). See source-varunneal-diffusion-will-be-everywhere.
  • The trade. Bigger batches raise throughput and inter-token latency together, until the step turns compute-bound (raw vLLM file, §"Benchmarks and auto-tuning").
  • Fewer bytes. Quantized weights cut memory and, when decode is bandwidth-bound, time (course module 07, "The quantization lab"; source-quantization-ground-up-ngrok).
