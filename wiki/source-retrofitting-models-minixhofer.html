Retrofitting LMs

source created 2026-05-06 updated 2026-05-06 model-training self-distillation fine-tuning architecture-modification 2026

Benjamin Minixhofer (Cambridge LTL) — blog post, 2026

A working definition: retrofitting = modifying both parameter values and the model architecture itself (changing "which parameters there are"), making it a strict superset of fine-tuning. The post crystallises the field into four ingredients that determine whether retrofitting succeeds without catastrophic capability loss.

Four Ingredients

  1. Self-Distillation — use the original model as teacher. On-policy distillation outperforms off-policy, which vastly outperforms no distillation. Reported as the single biggest lever, and underexplored.
  2. Architecture-Space Graduality — incrementally interpolate from original to target architecture instead of a hard swap.
  3. Expressivity Matching — the new architecture must be able to represent comparable function classes; otherwise capability collapse is unavoidable.
  4. Data Coverage — retrofitting data should match pretraining diversity; thin tails degrade tail-end performance.

Cited Applications

  • Tokenizer retrofitting (arXiv 2405.07883) and Bolmo byte-level retrofit (arXiv 2512.15586) — Minixhofer's own work.
  • Quantization-Aware Training (QAT).
  • KV cache sparsification (arXiv 2506.05345).
  • Multi-Token Prediction (arXiv 2511.11346).
  • LayerNorm removal (arXiv 2507.02559).
