The claim, plainly

Once a model is trained, you can still spend compute at answer time, either by searching over its outputs for the best one or by updating the model on the data in front of it. Search and learning feed each other: search finds better answers than the model gives on its own, training on those answers makes a better model, and the better model makes search cheaper (R, slides 3, 50–55).

Terms

  • Inference: in statistics, learning a model from data; in ML, using a trained model to answer new queries. The lecture uses the ML sense (R, slide 2).
  • Search: "given a model and a query, find the best answer to the query" (R, slide 3).
  • Verifier: a program or model that checks an answer, such as running code against tests (R, slide 22).

A map of where compute goes

The lecture sorts methods into three bands (R, slide 3):

BandJobExamples
Pre-traininggiven data, learn a model or representationgenerative modeling, representation learning
Post-traininggiven a model and new data, update the model (before deployment) or its behaviour (during it)fine-tuning, RLHF; prompting, in-context learning, test-time training, continual learning
Searchgiven a model and a query, find the best answerbest-of-N, beam search, MCTS, chain-of-thought

An arrow runs from search back to training: reinforcement learning, STaR, self-instruct, self-play (R, slide 3). The Bitter Lesson's two methods that scale with compute are "search and learning" (R, slide 4). OpenAI's o1 charts show AIME accuracy rising with both train-time and test-time compute (R, slide 5). In board games, Jones (2021) found test-time and train-time compute trade off at a fixed Elo: log₁₀(test) = −1.2 · log₁₀(train) + 0.004 · Elo + 29 (R, slide 9).

Key points

Decoding is a search problem. An autoregressive model trained by maximum likelihood with teacher forcing, each next token predicted from the true previous tokens, assigns a probability to every sequence (R, slides 12–14). Sampling or greedy decoding picks one token at a time; greedy decoding takes the most likely next token each step, which need not give the most likely whole sequence, because the best first token need not start the best sequence (R, slides 15–16).

Simple searches (R, slides 17–19):

  • Best-of-N: sample N sequences independently and keep the one with the highest likelihood (slide 17).
  • Beam search: keep the top-k partial sequences at each step, a form of tree search, then pick the most likely (slide 18).
  • Chain-of-thought: "emergent/learned search", the model writing out intermediate steps (slide 19, Wei et al. 2022).

Search for other scores. Search can maximise any scoring function, not only likelihood: the same caption candidates rank differently under a "fun-ness" scorer and a "scientific accuracy" scorer (R, slides 20–21). A verifier is one such scorer, with the key idea that "verification is easier than generation": checking that code computes Fibonacci is easier than writing it (R, slide 22). That holds where a cheap, reliable checker exists, such as unit tests or exact answers; a weak verifier lets wrong answers through, and search then amplifies them (the wiki's note).

Optimizing against human judgement. Generate images to maximise a score, such as CLIP similarity to a text through a VQGAN generator, or a model of human memorability (Isola's GANalyze, 2019): moving along a learned direction in the generator's latent space with strength α from −0.2 to 0.2 changes predicted memorability from 0.58 to 0.77 in one example (R, slides 26–31). Isola's "just ask" idea: chain-of-thought is "just ask for symbolic search"; prompting DALL·E with "very very … beautiful" is a crude "just ask for continuous reward optimization" (R, slides 32–40).

Updating the model at test time (R, slides 42–48).

  • In-context learning as gradient descent: in certain cases a transformer's output with context c equals the output of a model whose weights took one gradient step on c (von Oswald et al. 2023; slide 43). The result (per the paper, not captured) holds for a single linear self-attention layer trained on linear-regression tasks, and the gradient step updates an implicit linear model, not the transformer's own weights. A descent step is θ − λ∇L; the slide writes θ + λ∇L. So why not run gradient descent itself at test time? It is not learned, so it is guaranteed to improve fit on the context examples and can use more compute; but ICL might be a smarter learner than gradient descent (slide 44).
  • Test-time training: update the weights per test query; with few-shot examples this should help on them; with no labels, use a self-supervised task such as predicting masked parts (Sun et al. 2020; slides 45–46).
  • ARC: the slide credits Akyürek et al. (2024) with 61.9% on ARC, "current SOTA" as of the lecture, "mostly with an 'old' method", gradient descent on examples highly relevant to each test query, and asks whether fancy search is needed at all (slide 48). The paper's abstract gives the conditions: ARC's public validation set (the original ARC, now called ARC-AGI-1); 53.0% with test-time training alone on an 8B model; 61.9% when ensembled with program-synthesis methods (raw/arxiv-2411-07279-the-surprising-effectiveness-of-test-time.md, Abstract).

Search improves learning, learning improves search (R, slides 50–55).

  • Keep only verified answers and fine-tune on them (slides 50–51).
  • Games: search for winning action sequences, train a policy to make those moves, then let the policy guide the next search; AlphaGo (slides 52–53).
  • STaR: keep rationales that reach the right answer; for wrong ones, give the model the answer as a hint and ask it to rationalize; fine-tune on both; repeat (slide 54, Zelikman et al. 2022).
  • o1, as Sasha Rush speculated: search for chains of thought that solve problems, fine-tune toward them, repeat, and choose at deployment how much search to add (slide 55). Marked as speculation on the slide.

Which component it bears on

This section is the wiki's reading.

  • The decoder's output distribution. The model gives a probability for each next token; decoding is a search over the tree those probabilities define. Greedy is beam search with width 1; beam search keeps k branches; best-of-N samples leaves at random. Each trades compute for a better score, under whatever scorer you choose.
  • The verifier turns hard generation into easy checking; it is what lets search pay off and what makes the search-then-train loop safe from reinforcing wrong answers.
  • The weights at test time. ICL changes behaviour through the activations; test-time training changes the weights. The von Oswald result says the first can act like the second in special cases (slide 43).

Caveats

  • A survey lecture, Fall 2024; the o1 recipe is speculation (R, slide 55).
  • "61.9% on ARC … current SOTA" is the slide's claim at the time; 61.9% is test-time training plus program synthesis on the public validation set, and test-time training alone gives 53.0% (raw/arxiv-2411-07279-the-surprising-effectiveness-of-test-time.md, Abstract; full text not captured).
  • The memorability numbers are one example image (R, slide 30).
