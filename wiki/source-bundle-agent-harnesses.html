Agent Harnesses Source Bundle

source-bundle created 2026-05-14 updated 2026-09-25 source-bundle agents harness tool-use neural-symbolic developer-tools

This bundle condenses the agent-scaffolding cluster. The common claim is that much of today's "agent intelligence" lives outside the model: in tools, controller loops, memory stores, skill libraries, constrained generation, sandboxes, and evaluation harnesses.

Condensed Synthesis

The harness is the symbolic substrate. The LLM proposes, interprets, repairs, and ranks; the surrounding system owns state, tool legality, execution, memory, and sometimes search. This is why the cluster is central to concept-neural-symbolic-bridge: the bridge already exists operationally in agent runtimes.

The recurring pattern:

  • constrain model outputs into legal actions;
  • execute outside the model;
  • feed observations back into the transcript;
  • retain useful traces as memory, code, or skills;
  • add search or compilation when one-shot prompting is too weak.

Contradiction: the third step above ("feed observations back into the transcript") is what source-zhang-harness-blog says breaks generalization. Appending tool and sub-agent output to one context drifts it out of distribution; the post keeps that output in REPL variables the root model never reads (raw/web-2026-alexzhang-harness-compositional.md, §"The capacity for compositional generalization can live in the harness"; §"Equivalence classes over trajectories induced by the RLM harness"). The ReAct lineage in this bundle and the RLM post disagree on this step.
