Recurrent Depth: Latent Reasoning by Looping a Block

Summary

Here the extra room to think is not tokens but depth. The model has three parts: a prelude of 2 layers that embeds the input, a core block of 4 layers that runs r times, and a coda of 2 layers that predicts the next token. The core starts from random noise and at every step sees both its own last state and the embedded input again (R, §3.1, §3.2). With r = 32 the 8 real layers unfold to 132 (R, §3.2).

What supervises the loop: nothing but the ordinary next-token loss. During pretraining each sequence gets a random r, drawn from a heavy-tailed log-normal Poisson law centred on r̄ = 32, and gradients flow back through only the last 8 iterations, so memory does not grow with r (R, §3.3, §4.1). No chain-of-thought data is needed (R, §2).

The run: 800B tokens of public data, a mix of code, maths, science and web text, on up to 4,096 AMD GPUs of the Frontier supercomputer; two earlier runs failed when the hidden state collapsed, which the authors trace to norms and initialization (R, §4.1-4.3, Figure 5).

Key results

  • More loops, better answers: GSM8k CoT (8-shot, flexible match) rises from 0.00 at r = 1 to 42.08 at r = 32; ARC-Challenge 24.06 → 38.23 (R, Table 4). Easy tasks saturate early (HellaSwag near peak at 8 loops); GSM8k and HumanEval keep gaining (R, Figure 7).
  • Against its own non-looped twin trained the same way for 180B tokens: ARC-C 26.96 vs 29.18, HellaSwag 37.34 vs 48.80, GSM8k CoT 1.82 vs 9.02 (strict) (R, Table 4, §5.3).
  • Against open models: roughly level with OLMo-7B (first generation) on most tasks, behind later OLMo models (R, §5.1, Table 1). GSM8k 34.80 / 42.08 (strict / flexible) with a system prompt; OLMo-2-1124-7B scores 61.94 / 66.19 (R, Table 2). With weight averaging, 47.23% flexible at r = 64 (R, §5.4). The authors put test-time compute up to the FLOPs of a 50B-parameter fixed-depth model (R, §5.1).
  • Reasoning more than recall: on OpenBookQA with the relevant fact supplied, it gains 11.0 points (38.2 → 49.2), among the larger gains of the models compared (R, Table 5). More few-shot examples make it use more loops before saturating: about 8-12 with none, about 32 with 25-50 (R, §5.3, Figure 9).
  • Free extras: stopping each token when the KL divergence between two successive steps falls below 5 × 10⁻⁴ keeps MTBench at 5.56 vs 5.63; high-school maths exits sooner than moral scenarios, by 3.5 steps on average (R, §6.1). Sharing a 4-step KV cache across loops: MTBench 5.86 (R, §6.2). Starting each token's loop from the previous token's final state, which the authors liken to Coconut, cuts 1-2 steps (R, §6.3).
  • What the loop does: most token states converge to a point; some trace orbits, for example a number token in a GSM8k question; some drift steadily in one direction ("sliders"). Starting from different noise gives the same patterns (R, §7, Figures 11-12).

Caveats

  • One large run, a learning rate never cooled, an untested data mix; the authors call the model a proof of concept (R, §5.1, §10).
  • The looped model is compared to its non-looped twin only at 180B tokens (R, §5.3).
  • At r = 1 the final model scores 0.00 on GSM8k CoT and below its early checkpoint on SciQ (47.10 vs 54.10), so the non-looped path is not a usable fallback (R, Table 4).
  • Latent loops leave no text to check; the authors name the loss of oversight and offer the trajectory plots as a first answer (R, "Potential Implications of This Work").
