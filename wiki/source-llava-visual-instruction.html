LLaVA — Visual Instruction Tuning

source created 2026-05-06 updated 2026-05-06 multimodal vision-language instruction-tuning open-source visual-question-answering gpt-4

Authors: Haotian Liu, Chunyuan Li, Qingyang Wu, Yong Jae Lee (University of Wisconsin-Madison, Microsoft Research, Columbia) Date: 2023-04-17 (NeurIPS 2023, Oral) arXiv: 2304.08485

Summary

LLaVA is the canonical open-source recipe for turning an LLM into a chat-style multimodal assistant. The architectural trick is brutally simple: take a frozen source-clip-radford ViT-L/14 vision encoder, project its features into a frozen LLaMA's word-embedding space via a single trainable linear layer, and instruction-tune on multimodal data generated by language-only GPT-4. The result is an open-source model that approaches GPT-4V quality on instruction-following multimodal tasks, with a recipe simple enough to fit on a slide.

LLaVA's contribution is as much methodological as architectural — it introduced visual instruction tuning as a paradigm and showed that GPT-4 can author a high-quality multimodal instruction dataset from text-only inputs (image captions + bounding boxes + GPT-4-generated dialogue around them).

Architecture

[image] -> CLIP-ViT-L/14 -> [grid of visual features]
            -> linear projection W -> [tokens in LLaMA's embedding space]
            -> concatenate with text tokens -> LLaMA -> response
  • Vision encoder: frozen CLIP ViT-L/14 (the source-clip-radford checkpoint), grid features from the penultimate layer.
  • Projector: a single linear layer W mapping CLIP's 1024-dim grid features to LLaMA's 4096-dim word-embedding space. (LLaVA-1.5 later upgraded this to a 2-layer MLP.)
  • LLM: Vicuna (instruction-tuned LLaMA), 7B and 13B variants.

The radical simplification vs source-flamingo: no Perceiver Resampler, no gated cross-attention dense layers, no architectural surgery on the LM — just project the visual features into the input embedding space and let the LLM treat them as more tokens.

Two-Stage Training

  1. Pretraining for feature alignment: train only the projection W on 595K filtered CC3M (image, caption) pairs, with a single-turn instruction template. This aligns CLIP's visual feature distribution with LLaMA's word-embedding distribution. The vision encoder and LLM stay frozen.
  2. Visual instruction tuning: fine-tune the projection W and the LLM jointly on 158K GPT-4-generated multimodal instruction examples. Vision encoder still frozen.

GPT-4 Generated Instruction Data

Key data-generation insight: language-only GPT-4 (i.e. text-only, no vision) is given:

  • The image's COCO caption(s),
  • A list of object bounding boxes (as text),

and is asked to produce three kinds of multimodal instruction-response pairs:

  • Conversation (multi-turn Q&A about the image),
  • Detailed description,
  • Complex reasoning (questions requiring inference beyond what's literally visible).

This bootstraps a 158K multimodal instruction dataset entirely from language-only GPT-4 calls — no human annotation, no GPT-4V, just textual scene descriptions plus careful prompting.

Key Results

  • LLaVA-Bench: 85.1% relative score vs GPT-4 on a synthetic multimodal instruction-following benchmark.
  • ScienceQA: combining LLaVA + GPT-4 reaches 92.53% accuracy — new SOTA at the time.
  • Strong qualitative behavior on out-of-domain images, OCR-style queries, meme understanding (the famous "extreme ironing" example).
  • The whole stack (model, code, instruction data) was open-sourced — became the de facto open-source-VLM template for 2023-2024.

Significance

LLaVA's importance is partly the model itself — but mostly its demonstration that the simplest possible architectural choice + good instruction data approaches frontier VLM behavior. It catalyzed the open-source VLM ecosystem (LLaVA-1.5/1.6, MiniGPT-4, ShareGPT4V, InstructBLIP, mPLUG-Owl, Qwen-VL, etc.), all of which inherit some combination of:

  • The CLIP-ViT vision encoder + linear/MLP projection + decoder LLM stack;
  • The two-stage train (projector pretraining → joint instruction tuning);
  • The language-model-as-data-author approach to instruction synthesis.

It also represents the architectural endpoint of a trajectory: source-flamingo used heavy adapter machinery (gated cross-attention, Perceiver Resampler), then BLIP-2 simplified to a Q-Former, and LLaVA simplified further to a single linear layer. This trajectory — that vision tokens can simply live in the LLM's input space if you have decent data — is now the dominant recipe.

The contrast with source-vl-jepa is illuminating: LLaVA learns to generate text tokens conditioned on visual tokens (token-space VLM); VL-JEPA argues you should instead predict the embedding of the target text directly, which uses ~50% fewer trainable params and beats CLIP-style models on video benchmarks. Same problem, opposite answer about whether token-space generation is the right interface.
